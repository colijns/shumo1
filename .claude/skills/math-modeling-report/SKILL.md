# 数学建模问题报告

把一道赛题的工作结果写成正式问题报告，输出到 `docs/问题X（n）报告.md`，按六段式组织。**核心约束是自包含**：成品报告必须独立可读，读者无需查阅任何其他文件即可理解全部内容。所有口径数值、术语定义、建模抉择依据都要内联写进报告正文，不得出现"见 XX 文档""与 Q1/Q2 对齐""遵循 CONTEXT.md""见 ADR 000X"等外部引用。

创作过程中**可以**读 `docs/赛题结构化拆解.md`、`Qx/` 代码与 `CONTEXT.md`、`docs/adr/`、`docs/问题X（n）.md`、`output/` 作为信息源——但取出的信息要写进报告本身，而非以引用形式留在成品里。读得到 ≠ 引用得到。

## Obsidian Markdown 规范

报告采用 Obsidian Flavored Markdown 格式。以下 Obsidian 特有语法在报告中为**强制要求**（除非标注为可选），不可降级为纯 CommonMark。

### Frontmatter（必须）

每份报告必须以 YAML frontmatter 开头，包含以下属性：

```yaml
---
title: 问题X（n）报告
date: YYYY-MM-DD
tags:
  - 数学建模
  - 微电网
  - <题目关键词>
aliases:
  - QX(n) 报告
status: done
---
```

属性说明：
- `title`：报告标题，格式 `问题X（n）报告`
- `date`：成文日期
- `tags`：至少包含 `数学建模`、`微电网` 以及题号标签（如 `Q2`）
- `aliases`：别名，方便 Obsidian wikilink 引用
- `status`：`done`（定稿）/ `draft`（草稿）

### 数学公式（必须）

- **块级公式**：必须用 `$$…$$` 包围，独占一行/多行，不得使用 `\displaystyle` 硬凑行内
- **行内公式**：用 `$…$` 包围
- 约束条件编号用 `\tag{…}` 或行末 `\qquad (n)`

```markdown
功率平衡约束：
$$
P_t^{pv} + P_t^{wt} + P_t^{grid} + P_t^{dis} = L_t + P_t^{ch} \qquad \forall t \in T
$$

单位供电成本定义为 $C_{unit} = \frac{C_{total}}{\sum_t L_t}$。
```

### Callouts（必须）

用 Obsidian callout 标记关键信息块。以下类型为推荐用法：

| Callout 类型 | 用途 | 示例场景 |
|-------------|------|---------|
| `> [!important]` | 核心假设、关键约束 | 模型假设摘要、不可违反的硬约束 |
| `> [!warning]` | 注意事项、局限性 | 适用边界、假设敏感项 |
| `> [!success]` | 关键结论、最佳结果 | 最优方案数值、对比结论 |
| `> [!info]` | 补充说明、参数注释 | 参数取值依据、口径定义 |
| `> [!question]` | 待验证项、开放问题 | 敏感性待测参数、模型扩展方向 |
| `> [!example]` | 计算示例、案例演示 | 典型场景演算、公式代入示例 |
| `> [!tip]` | 建模技巧、方法要点 | 为何选择此方法、算法优化点 |

折叠 callout 用于冗长推导或补充材料：
```markdown
> [!info]- 详细推导（点击展开）
> 此处为完整推导过程……
```

### 高亮（推荐）

关键数值和结论用 `==text==` 高亮：
```markdown
联合运营方案的单位供电成本为 ==0.487 元/kWh==，较独立运营降低 ==12.3%==。
```

### 脚注（推荐）

对需要补充说明但不适合放在正文的内容，使用脚注：
```markdown
储能投资按 10 年寿命线性年化[^1]。

[^1]: 题目未给定贴现率，故不计贴现。若引入 5% 贴现率，年化系数将从 0.10 升至 0.1295。
```

### 标签（可选）

正文中可使用 `#tag` 标记关键概念：
```markdown
模型的核心约束是 #功率平衡 和 #SOC边界。
```

### 嵌入（不适用）

报告中**不使用** `![[embed]]` 语法——报告须自包含，不得嵌入其他文件。图片用标准 markdown 语法 `![alt](path)` 引用。

## 执行步骤

1. **定位本题材料**
   - 读 `docs/赛题结构化拆解.md` 取本题显性任务、已知参数、硬约束、难点
   - 读对应题号目录 `Qx/`：代码、`CONTEXT.md`、`docs/adr/`、`output/`，取实际数值结果与建模抉择理由
   - 读 `docs/问题X（n）.md`（若存在）取已有分析
   - 完成：能列出"任务 + 参数 + 已得数值 + 抉择理由"四栏，每栏非空

2. **写入 frontmatter**
   - 按 §Obsidian Markdown 规范 §Frontmatter 写 YAML 头
   - 完成：`title`、`date`、`tags`、`aliases`、`status` 五字段齐全

3. **按六段式落稿**
   - 标题严格用 `## 一、问题分析` … `## 六、结论`（中文序号 + 顿号，区别于工作文档的 `## 1.`）
   - 依下文 §段落规格 逐段填写，各段的 callout 按推荐类型使用
   - 数学公式严格用 `$$…$$`（块级）和 `$…$`（行内）
   - 完成：六段标题齐全，每段满足其"必须包含"清单

4. **内联化**
   - 把 §口径清单 的数值写进报告的 §模型假设 或 §参数取值表，作为本报告自含参数，不标注"来自其他文档"
   - 建模抉择类假设（充电计价、SOC 边界、投资折算、典型日 ×365）在假设条目内直接写明依据：来源（题目明示 / 工程惯例 / 建模抉择）+ 一句理由，不指向 ADR 编号
   - 术语在报告内首次出现处给出定义，或集中列一节术语表
   - 完成：报告内任何口径、术语、抉择都能在本文内查到完整说明

5. **数值核对**
   - 报告每个数值与代码输出或 `CONTEXT.md` 逐一对齐，统一 3 位小数
   - 完成：零数值不一致

6. **自包含校验**
   - 报告不得出现指向**本仓库其他文件**的引用。检索以下痕迹，命中即缺陷，改写为内联表述：
     - 仓库路径：`docs/`、`CONTEXT.md`、`adr/`、`output/`、`赛题结构化拆解`、`Q1/`、`Q2/`
     - 外指话术：`见 …文档`、`见 …文件`、`参见 …`、`详见 …`、`与 …对齐`、`遵循 …`、`同 …口径`（省略号指本仓库其他文件/文档时）
     - ADR 编号：`ADR 000`、`0001`、`0002`、`0003`…
   - 指向**报告自身**的引用允许：如"见下表""详见 §三""同口径对比"（指本文内的对比）不视为缺陷
   - 完成：外指痕迹在正文（含表格、公式、注释、checkbox）中零命中

7. **Obsidian 语法校验**
   - frontmatter 格式正确（YAML 闭合 `---`）
   - 数学公式全部用 `$$…$$`（块级）/ `$…$`（行内），无裸 LaTeX 命令
   - callout 语法正确：`> [!type]` 后空一格再接内容
   - 脚注编号唯一，定义完整
   - 无 `![[embed]]` 语法（报告须自包含）
   - 完成：上述检查项全部通过

8. **落盘**
   - 写到 `docs/问题X（n）报告.md`
   - 完成：文件写入，frontmatter 与六段标题在文件中各出现一次

## 段落规格

### 一、问题分析
必须包含：
- 显性任务（要算什么、输出哪些指标）
- 与前后题的口径差异（独立 vs 联合、典型日 vs 全年、固定 vs 分时电价）——差异须在本报告内讲清，不靠读者去翻其他题报告
- 输入数据来源（附件几 + 本题目录），写明即可，不要求读者打开

推荐 callout：
```markdown
> [!info] 与本问题其他子题的差异
> 本题与问题 X(1) 的核心差异在于……
```

### 二、模型假设
必须包含：
- 编号假设清单，集中列出，不散落在各节
- 每条标注依据来源：题目明示 / 工程惯例 / 建模抉择；抉择类须附一句理由，理由内联写明，不指向 ADR

推荐 callout——在假设清单前加关键假设摘要：
```markdown
> [!important] 核心假设
> - 购电成本：光伏 ==0.4==、风电 ==0.5==、电网 ==1.0== 元/kWh
> - 储能充放电效率 ==0.95==，SOC 范围 ==10%～90%==
> - 典型日 × 365 估算全年
```

### 三、模型建立
必须包含：
- 集合与时段定义
- 决策变量表（符号 | 含义 | 单位）
- 约束条件（逐条编号，LaTeX，块级公式用 `$$…$$`）
- 目标函数（LaTeX，块级公式用 `$$…$$`）
- 参数取值表（口径数值全部落表，作为本报告自含参数）

推荐 callout——参数取值表前加参数来源说明：
```markdown
> [!info] 参数取值依据
> 购电价格取自题目给定水平，储能单价取自行业均价参考……
```

### 四、结果与分析
必须包含：
- 结果汇总表（方案 | 指标 | 数值）
- 同口径对比（独立 vs 联合、有无储能）——对比所需数值须全部出现在本报告内
- 机理分析：为什么是这个结果，不只报数字

推荐 callout：
```markdown
> [!success] 关键发现
> 联合运营方案的单位供电成本为 ==0.487 元/kWh==，较独立运营降低 ==12.3%==。
> 降幅主要来自园区间互济减少了 ==15%== 的电网购电。

> [!warning] 注意
> 上述结论建立在储能投资 10 年线性年化的基础上。若储能成本上升 20%，联合运营优势将缩窄至 5% 以内。
```

### 五、模型检验
必须包含：
- 功率平衡残差 < 1e-4
- 约束满足校验（SOC 区间、充放互斥、变量非负）
- 敏感性分析（至少一个关键参数）
- 检查项 checkbox 清单（`- [ ]` / `- [x]`）

推荐 callout：
```markdown
> [!question] 待进一步验证
> - 储能投资成本 ±30% 敏感性
> - 分时电价场景扩展
```

### 六、结论
必须包含：
- 一段话数值结论
- 适用边界：哪些假设变化会推翻结论

推荐 callout：
```markdown
> [!success] 数值结论
> 联合运营 + 储能配置 XX kW / XX kWh 方案下，单位供电成本为 ==XX 元/kWh==，
> 全年总成本为 ==XX 万元==。

> [!warning] 适用边界
> 以下假设若发生变化，结论可能被推翻：
> - ……
> ```

## 口径清单

以下口径须在报告正文（§模型假设 或 §参数取值表）内联写明，作为本报告自含参数，不标注"来自其他文档"：

- 购电成本：光伏 0.4、风电 0.5、电网 1.0 元/kWh
- 储能：充放电效率 0.95、SOC 10%~90%、功率 800 元/kW、容量 1800 元/kWh、寿命 10 年
- 不向电网售电；弃电不计成本；消纳计成本（储能充电属消纳，须在假设条目内直接写明理由）
- 典型日 × 365 估算全年
- 单位供电成本分母 = 实际负荷电量（非发电量、非购电量）
- 联合运营：先聚合后平衡，不计园区间损耗与结算
- 投资线性年化、不贴现、无残值（题目未给贴现率）
- 风光优先消纳、不足才网购

## 术语表

报告内统一使用以下词，首次出现处给出定义（若另立术语表小节则集中列出），不指向 `CONTEXT.md`：

- 联合运营 / 独立运营
- 园区间互济
- 风光消纳 / 弃风弃光 / 风光消纳率
- 单位供电成本
- 储能 SOC、充放电互斥

## 写作风格

### Obsidian 格式规范

- **Frontmatter**：文件开头 YAML 块，`title`/`date`/`tags`/`aliases`/`status` 五字段齐全
- **数学公式**：
  - 块级公式必须用 `$$…$$` 包围，独占行，不得用 `\displaystyle` 在行内硬凑
  - 行内公式用 `$…$` 包围
  - 约束条件编号用 `\tag{…}` 或行末 `\qquad (n)`
  - 公式内如需换行，用 `\begin{aligned}` 等环境包裹在 `$$…$$` 内
- **Callout**：关键信息块用 `> [!type]` 标记（见 §段落规格 各段推荐用法）
  - 折叠 callout 用 `> [!type]-`（默认折叠）或 `> [!type]+`（默认展开）
  - callout 内可嵌套标准 markdown（列表、代码块、公式等）
- **高亮**：关键数值和结论用 `==text==` 高亮，不用粗体 `**text**` 代替
- **脚注**：补充说明用 `[^n]` 脚注，定义在文末；正文引用与定义编号一一对应
- **标签**（可选）：正文内用 `#标签` 标记关键概念，frontmatter 中 `tags:` 列表为正式标签
-  **嵌入（禁用）**：报告不使用 `![[embed]]` 语法

### 通用规范

- **表格**：markdown 表格，列对齐用 `|:---|`（左）/ `|---:|`（右）/ `|:---:|`（居中）
- **数值**：统一 3 位小数
- **em dash**：用 U+2014（—）；Edit 匹配失败时按行号替换或用 PowerShell `[char]0x2014` 构造
- **配图**：`savefig` 写出图片文件，报告中用 `![图题](路径)` 引用；不用 `plt.show`
- **章节引用**：指向报告自身的引用用 `§段落名` 格式（如 `详见 §三`），不写"见上文""见下文"

### 格式检查清单

落盘前逐项确认：
- [ ] frontmatter 五行齐全，YAML `---` 闭合正确
- [ ] 所有块级公式用 `$$…$$`，无裸 `\[…\]` 或 `\displaystyle`
- [ ] 所有行内公式用 `$…$`
- [ ] 至少 3 处 callout，类型不重复
- [ ] 关键数值用 `==…==` 高亮（至少 3 处）
- [ ] 无 `![[embed]]` 语法
