# 复用 Q1 统一 MILP 模型实现 Q2 各小问

## 背景

问题2 各小问（联合无储能、共享储能配置、灵敏度分析）都需要与问题1 完全一致的成本口径（`C_PV=0.4`、`C_W=0.5`、`C_G=1.0`、`DT=1`、弃电不计成本、典型日×365）。`docs/问题2（1）.md` §4.5 明确建议"仍调用统一 MILP 模型，并将储能功率、容量设为 0"。

## 决策

Q2 通过 `sys.path.append('../Q1')` 跨目录 import `data_loader`（数据加载与常量）和 `milp_model.run_no_storage`（储能置0即退化为无储能模型），不复制算法代码。联合无储能只需把三园区逐时相加后的 `L^J / G^{pv,J} / G^{w,J}` 喂给 `run_no_storage`。

## Considered Options

- **复用 Q1（import）—— 采用**：口径天然一致，Q2(2)/(3) 可继续复用同一模型；代价是 Q2 非单文件独立。
- **复制模型到 Q2/**：自包含，但易与 Q1 口径漂移、代码重复，Q2(2)/(3) 还要再复制。
- **Q2 内新写轻量联合 LP**：最简，但偏离文档"调用统一模型"的建议，Q2(2) 共享储能时仍需另写。

## Consequences

- Q2 破坏了 `templates/` 的"单文件独立"约定；该约定本就只针对模板库，Q1 内部已跨文件 import，Q2 沿用此模式。
- Q1 的 `data_loader`/`milp_model` 接口一旦改动，Q2 会受影响——这是有意的耦合，以保证两问口径永远一致。
- 后续 Q2(2)/(3) 在此基础上扩展共享储能，直接复用 `solve_park_optimization` 的容量优化分支。
